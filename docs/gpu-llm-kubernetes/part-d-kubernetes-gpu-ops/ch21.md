## TensorFlow GPU configuration

<pre><code><span class="gm-k">import</span> os, tensorflow <span class="gm-k">as</span> tf

<span class="gm-c"># Environment knobs (set before TF initializes CUDA)</span>
os.environ[<span class="gm-s">'TF_GPU_ALLOCATOR'</span>] = <span class="gm-s">'cuda_malloc_async'</span>   <span class="gm-c"># async allocator: less fragmentation</span>
os.environ[<span class="gm-s">'TF_GPU_THREAD_MODE'</span>] = <span class="gm-s">'gpu_private'</span>       <span class="gm-c"># dedicated host threads per GPU for launches</span>
os.environ[<span class="gm-s">'TF_GPU_THREAD_COUNT'</span>] = <span class="gm-s">'2'</span>
os.environ[<span class="gm-s">'TF_CUDNN_USE_AUTOTUNE'</span>] = <span class="gm-s">'1'</span>             <span class="gm-c"># benchmark conv algorithms on first run</span>
os.environ[<span class="gm-s">'TF_ENABLE_ONEDNN_OPTS'</span>] = <span class="gm-s">'1'</span>             <span class="gm-c"># CPU-side oneDNN kernels for preprocessing</span>

gpus = tf.config.list_physical_devices(<span class="gm-s">'GPU'</span>)
<span class="gm-k">if</span> gpus:
    <span class="gm-c"># Option A: grow memory on demand (share GPU with other processes)</span>
    <span class="gm-k">for</span> g <span class="gm-k">in</span> gpus:
        tf.config.experimental.set_memory_growth(g, <span class="gm-k">True</span>)
    <span class="gm-c"># Option B (mutually exclusive with A): hard cap, e.g. one MIG-like slice</span>
    <span class="gm-c"># tf.config.set_logical_device_configuration(gpus[0],</span>
    <span class="gm-c">#     [tf.config.LogicalDeviceConfiguration(memory_limit=10240)])</span>

<span class="gm-c"># Mixed precision on Ampere/Hopper: tensor cores + half the activation memory</span>
tf.keras.mixed_precision.set_global_policy(<span class="gm-s">'mixed_bfloat16'</span>)   <span class="gm-c"># bf16 avoids loss scaling; use 'mixed_float16' on V100</span></code></pre>
<div class="gm-warn"><b>Correction to the original guide</b>The original snippet set memory growth <em>and</em> a virtual device memory limit on the same GPU. TensorFlow raises an error if both are set; pick one. It also used <code>mixed_float16</code> for A100 — <code>mixed_bfloat16</code> is the better choice on Ampere and newer because it needs no loss scaling.</div>

## Input pipeline: the CPU side of Chapter 4, in code

<pre><code>AUTOTUNE = tf.data.AUTOTUNE

<span class="gm-k">def</span> create_dataset(file_pattern, batch_size):
    ds = tf.data.Dataset.list_files(file_pattern, shuffle=<span class="gm-k">True</span>)
    ds = ds.interleave(tf.data.TFRecordDataset,          <span class="gm-c"># read many shards in parallel</span>
                       cycle_length=AUTOTUNE, num_parallel_calls=AUTOTUNE, deterministic=<span class="gm-k">False</span>)
    ds = ds.map(parse_fn, num_parallel_calls=AUTOTUNE)   <span class="gm-c"># decode/augment on the pinned CPU cores</span>
    ds = ds.cache()                                      <span class="gm-c"># only if it fits in RAM/NVMe; else cache(filename=...)</span>
    ds = ds.shuffle(10_000)
    ds = ds.batch(batch_size, drop_remainder=<span class="gm-k">True</span>)
    <span class="gm-k">return</span> ds.prefetch(AUTOTUNE)                        <span class="gm-c"># overlap next-batch prep with GPU compute</span>

<span class="gm-c"># Sanity check: if this loop alone can't hit &gt; GPU steps/sec, the GPU will starve</span>
<span class="gm-k">for</span> _ <span class="gm-k">in</span> create_dataset(<span class="gm-s">"/data/train-*.tfrecord"</span>, 256).take(100): <span class="gm-k">pass</span></code></pre>

## Deploying an inference engine on Kubernetes

<pre><code>apiVersion: apps/v1
kind: Deployment
metadata: {name: llm-70b}
spec:
  replicas: 2
  template:
    spec:
      runtimeClassName: nvidia
      nodeSelector: {nvidia.com/gpu.product: NVIDIA-H100-80GB-HBM3}
      containers:
      - name: vllm
        image: vllm/vllm-openai:latest
        args: [<span class="gm-s">"--model"</span>, <span class="gm-s">"/models/llm-70b"</span>, <span class="gm-s">"--tensor-parallel-size"</span>, <span class="gm-s">"4"</span>,
               <span class="gm-s">"--max-model-len"</span>, <span class="gm-s">"32768"</span>, <span class="gm-s">"--gpu-memory-utilization"</span>, <span class="gm-s">"0.92"</span>,
               <span class="gm-s">"--enable-prefix-caching"</span>, <span class="gm-s">"--enable-chunked-prefill"</span>]
        ports: [{containerPort: 8000}]
        resources:
          requests: {cpu: <span class="gm-s">"16"</span>, memory: <span class="gm-s">"256Gi"</span>, nvidia.com/gpu: <span class="gm-s">"4"</span>}
          limits:   {cpu: <span class="gm-s">"16"</span>, memory: <span class="gm-s">"256Gi"</span>, nvidia.com/gpu: <span class="gm-s">"4"</span>}
        volumeMounts:
        - {name: models, mountPath: /models}
        - {name: shm, mountPath: /dev/shm}            <span class="gm-c"># NCCL needs large shared memory for TP</span>
        readinessProbe: {httpGet: {path: /health, port: 8000}, initialDelaySeconds: 120}
        startupProbe:   {httpGet: {path: /health, port: 8000}, failureThreshold: 60, periodSeconds: 10}
      volumes:
      - name: models
        hostPath: {path: /mnt/nvme-raid0/models}      <span class="gm-c"># node-local weight cache (Ch. 11)</span>
      - name: shm
        emptyDir: {medium: Memory, sizeLimit: 32Gi}</code></pre>
<p>Autoscale on engine metrics, not CPU: vLLM exposes <code>vllm:num_requests_waiting</code> and <code>vllm:gpu_cache_usage_perc</code>; KEDA or a custom-metrics HPA can scale replicas when the queue grows. Because cold starts take minutes, scale up early and down slowly.</p>
