## Kubelet configuration

<pre><code><span class="gm-c"># kubelet configuration (per node, in the node pool's kubelet config)</span>
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
cpuManagerPolicy: <span class="gm-s">"static"</span>            <span class="gm-c"># pin Guaranteed pods to exclusive cores</span>
cpuManagerReconcilePeriod: <span class="gm-s">"10s"</span>
memoryManagerPolicy: <span class="gm-s">"Static"</span>         <span class="gm-c"># NUMA-local memory for Guaranteed pods</span>
topologyManagerPolicy: <span class="gm-s">"single-numa-node"</span>   <span class="gm-c"># or best-effort / restricted</span>
topologyManagerScope: <span class="gm-s">"pod"</span>            <span class="gm-c"># align all containers of the pod together</span>
reservedSystemCPUs: <span class="gm-s">"0,1"</span>              <span class="gm-c"># kubelet, kube-proxy, daemons stay here</span>
reservedMemory:
  - numaNode: 0
    limits: {memory: 1Gi}
  - numaNode: 1
    limits: {memory: 1Gi}</code></pre>
<table>
<tbody><tr><th>Topology policy</th><th>Behaviour</th><th>Use when</th></tr>
<tr><td><code>none</code></td><td>No alignment (default)</td><td>Never on GPU nodes</td></tr>
<tr><td><code>best-effort</code></td><td>Prefer a single NUMA node; admit anyway if impossible</td><td>Mixed clusters where admission failures are worse than slowness</td></tr>
<tr><td><code>restricted</code></td><td>Admit only if the preferred alignment is possible; else pod stays Pending with <code>TopologyAffinityError</code></td><td>Production inference</td></tr>
<tr><td><code>single-numa-node</code></td><td>Everything (CPUs, memory, GPU, NIC) on one NUMA node or reject</td><td>Latency-critical, single-GPU pods</td></tr>
</tbody></table>
<div class="gm-warn"><b>Changing the CPU Manager policy requires a node drain</b>The static policy keeps state in <code>/var/lib/kubelet/cpu_manager_state</code>. Switching policy on a live node fails kubelet startup until that file is removed; plan it as a rolling node-pool replacement.</div>

## Pod spec for a pinned, NUMA-aligned GPU trainer

<pre><code>apiVersion: v1
kind: Pod
metadata:
  name: gpu-training
spec:
  runtimeClassName: nvidia
  nodeSelector:
    nvidia.com/gpu.product: NVIDIA-A100-SXM4-80GB
  containers:
  - name: trainer
    image: registry.example.com/trainer:1.4
    resources:
      requests:
        cpu: <span class="gm-s">"8"</span>          <span class="gm-c"># whole number → eligible for exclusive cores</span>
        memory: <span class="gm-s">"64Gi"</span>
        nvidia.com/gpu: <span class="gm-s">"1"</span>
      limits:
        cpu: <span class="gm-s">"8"</span>          <span class="gm-c"># must equal requests → Guaranteed</span>
        memory: <span class="gm-s">"64Gi"</span>     <span class="gm-c"># must equal requests</span>
        nvidia.com/gpu: <span class="gm-s">"1"</span>
    env:
    - name: OMP_NUM_THREADS
      value: <span class="gm-s">"8"</span>          <span class="gm-c"># match the core count you were given</span></code></pre>
<div class="gm-danger"><b>Correction to the original guide</b>The original "Incident Pattern 1" pod used <code>cpu: "4000m"</code> for requests and limits. Millicore values — even equal ones like 4000m — do <em>not</em> qualify for exclusive cores under the static CPU Manager; only integer CPU quantities (<code>"4"</code>) do. The pod would be Guaranteed but still share the CPU pool. Use <code>cpu: "4"</code>.</div>

## Verifying pinning on the node

<pre><code><span class="gm-c"># Which cores did the container get?</span>
kubectl exec gpu-training -- cat /sys/fs/cgroup/cpuset.cpus.effective     <span class="gm-c"># cgroup v2</span>
kubectl exec gpu-training -- cat /sys/fs/cgroup/cpuset/cpuset.cpus         <span class="gm-c"># cgroup v1</span>
kubectl exec gpu-training -- taskset -cp 1

<span class="gm-c"># Kubelet's view</span>
cat /var/lib/kubelet/cpu_manager_state | jq .

<span class="gm-c"># NUMA node of the GPU vs the cores</span>
cat /sys/bus/pci/devices/0000:17:00.0/numa_node
nvidia-smi topo -m</code></pre>

## CPU throttling detection (Burstable pods)

<pre><code><span class="gm-c"># cgroup v2 (most modern nodes)</span>
kubectl exec pod-name -- cat /sys/fs/cgroup/cpu.stat
<span class="gm-c"># nr_periods, nr_throttled, throttled_usec — ratio nr_throttled/nr_periods &gt; 5% is a problem</span>

<span class="gm-c"># cgroup v1 (older nodes; the paths in the original guide)</span>
kubectl exec pod-name -- cat /sys/fs/cgroup/cpu/cpu.stat

<span class="gm-c"># Cluster-wide via Prometheus (cAdvisor metrics)</span>
rate(container_cpu_cfs_throttled_periods_total[5m]) / rate(container_cpu_cfs_periods_total[5m]) &gt; 0.05</code></pre>
<p>When a GPU pod shows throttling, the fix is almost never "raise the limit" — it's "make it Guaranteed with integer cores" so the CFS quota mechanism is not involved at all.</p>

## Burstable: when it is the right choice

<div class="gm-grid2">
<div class="gm-card"><b>Good fit</b>Inference with spiky request patterns where extra CPU is only needed for tokenization bursts · dev/notebook environments · preprocessing jobs where cost matters more than tail latency</div>
<div class="gm-card"><b>Bad fit</b>Training (needs steady feeding) · latency-SLO inference (throttling = p99 spikes) · anything sharing a node with a Guaranteed GPU pod you care about (burst steals the shared pool)</div>
</div>
<pre><code>apiVersion: v1
kind: Pod
metadata:
  name: burstable-inference
spec:
  containers:
  - name: inference-service
    resources:
      requests: {cpu: <span class="gm-s">"2"</span>, memory: <span class="gm-s">"4Gi"</span>, nvidia.com/gpu: <span class="gm-s">"1"</span>}
      limits:   {cpu: <span class="gm-s">"8"</span>, memory: <span class="gm-s">"16Gi"</span>, nvidia.com/gpu: <span class="gm-s">"1"</span>}   <span class="gm-c"># bursts to 8 when idle CPU exists</span></code></pre>

## Node feature discovery and GPU node labels

<p>The NVIDIA GPU Operator installs Node Feature Discovery and the GPU Feature Discovery add-on, which label nodes with facts you can select on: <code>nvidia.com/gpu.product</code>, <code>nvidia.com/gpu.memory</code>, <code>nvidia.com/gpu.count</code>, <code>nvidia.com/mig.capable</code>, <code>feature.node.kubernetes.io/cpu-cpuid.AVX512F</code>, plus driver and CUDA versions. Prefer these over hand-maintained labels like <code>numa-topology: optimized</code> from the original guide, which drift.</p>
