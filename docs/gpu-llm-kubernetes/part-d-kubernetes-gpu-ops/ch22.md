## Metrics that matter

<table>
<tbody><tr><th>Metric</th><th>Meaning</th><th>Healthy range</th></tr>
<tr><td><code>DCGM_FI_DEV_GPU_UTIL</code></td><td>% of time a kernel was running</td><td>85–95% training; 70–90% inference — but see Chapter 4's caveat</td></tr>
<tr><td><code>DCGM_FI_PROF_SM_ACTIVE</code></td><td>% of SMs busy (profiling metric)</td><td>&gt; 60% for a well-fed job</td></tr>
<tr><td><code>DCGM_FI_PROF_PIPE_TENSOR_ACTIVE</code></td><td>tensor-core pipe utilization</td><td>&gt; 30% means you are actually using mixed precision</td></tr>
<tr><td><code>DCGM_FI_PROF_DRAM_ACTIVE</code></td><td>HBM bandwidth utilization</td><td>high during LLM decode (expected)</td></tr>
<tr><td><code>DCGM_FI_DEV_FB_USED</code> / <code>FB_FREE</code></td><td>GPU memory used / free (MiB)</td><td>80–90% used; leave headroom</td></tr>
<tr><td><code>DCGM_FI_DEV_GPU_TEMP</code></td><td>die temperature</td><td>&lt; 80 °C; alert 85 °C</td></tr>
<tr><td><code>DCGM_FI_DEV_POWER_USAGE</code></td><td>watts</td><td>near TDP is normal under load; pinned at cap → clock throttling</td></tr>
<tr><td><code>DCGM_FI_DEV_CLOCK_THROTTLE_REASONS</code></td><td>bitmask: power cap, thermal, HW slowdown</td><td>0</td></tr>
<tr><td><code>DCGM_FI_DEV_XID_ERRORS</code></td><td>last Xid (driver error code)</td><td>0; Xid 79 = fell off the bus, 48 = double-bit ECC, 31/43 = app fault</td></tr>
<tr><td><code>DCGM_FI_DEV_ECC_DBE_VOL_TOTAL</code></td><td>uncorrectable memory errors</td><td>0 — non-zero means RMA the card</td></tr>
<tr><td><code>DCGM_FI_DEV_PCIE_REPLAY_COUNTER</code></td><td>PCIe link retries</td><td>flat; rising = bad slot/riser</td></tr>
<tr><td><code>DCGM_FI_DEV_NVLINK_BANDWIDTH_TOTAL</code></td><td>NVLink traffic</td><td>non-zero during TP/DDP</td></tr>

## dcgm-exporter DaemonSet

<pre><code>apiVersion: apps/v1
kind: DaemonSet
metadata: {name: dcgm-exporter, namespace: gpu-monitoring}
spec:
  selector: {matchLabels: {app: dcgm-exporter}}
  template:
    metadata: {labels: {app: dcgm-exporter}}
    spec:
      runtimeClassName: nvidia
      nodeSelector: {nvidia.com/gpu.present: <span class="gm-s">"true"</span>}
      tolerations: [{key: nvidia.com/gpu, operator: Exists, effect: NoSchedule}]
      containers:
      - name: dcgm-exporter
        image: nvcr.io/nvidia/k8s/dcgm-exporter:3.3.9-3.6.1-ubuntu22.04   <span class="gm-c"># pin to the version matching your driver</span>
        ports: [{name: metrics, containerPort: 9400}]
        env:
        - {name: DCGM_EXPORTER_KUBERNETES, value: <span class="gm-s">"true"</span>}     <span class="gm-c"># adds pod/namespace labels</span>
        - {name: DCGM_EXPORTER_COLLECTORS, value: <span class="gm-s">"/etc/dcgm-exporter/dcp-metrics-included.csv"</span>}
        - {name: DCGM_EXPORTER_INTERVAL, value: <span class="gm-s">"15000"</span>}
        securityContext: {capabilities: {add: [SYS_ADMIN]}}   <span class="gm-c"># for profiling metrics; avoid full privileged</span>
        volumeMounts:
        - {name: pod-resources, mountPath: /var/lib/kubelet/pod-resources, readOnly: true}
      volumes:
      - name: pod-resources
        hostPath: {path: /var/lib/kubelet/pod-resources}</code></pre>
<div class="gm-note"><b>Simplest path</b>The NVIDIA GPU Operator installs driver, container toolkit, device plugin, GFD, MIG manager and dcgm-exporter together, with versions that are tested against each other. Hand-rolling these (as the original guide's manifests did) is how you end up with the driver/exporter mismatches described in "Incident Pattern 3".</div>

## Alerting rules

<pre><code>groups:
- name: gpu-critical
  rules:
  - alert: GPUMemoryExhaustion
    expr: DCGM_FI_DEV_FB_USED / (DCGM_FI_DEV_FB_USED + DCGM_FI_DEV_FB_FREE) &gt; 0.97
    for: 5m
    labels: {severity: critical}
    annotations: {summary: <span class="gm-s">"GPU {{ $labels.gpu }} on {{ $labels.Hostname }} memory &gt; 97% (pod {{ $labels.pod }})"</span>}

  - alert: GPUTemperatureCritical
    expr: DCGM_FI_DEV_GPU_TEMP &gt; 85
    for: 2m
    labels: {severity: critical}

  - alert: GPUXidError
    expr: increase(DCGM_FI_DEV_XID_ERRORS[10m]) &gt; 0
    labels: {severity: critical}
    annotations: {summary: <span class="gm-s">"Xid {{ $value }} on {{ $labels.Hostname }} — check dmesg, consider cordon"</span>}

  - alert: GPUUncorrectableECC
    expr: increase(DCGM_FI_DEV_ECC_DBE_VOL_TOTAL[1h]) &gt; 0
    labels: {severity: critical}

- name: gpu-efficiency
  rules:
  - alert: GPUAllocatedButIdle
    <span class="gm-c"># a pod holds the GPU (label present) yet SM activity is low for 30 min: starved, hung, or forgotten</span>
    expr: avg_over_time(DCGM_FI_PROF_SM_ACTIVE{pod!=<span class="gm-s">""</span>}[30m]) &lt; 0.2
    for: 30m
    labels: {severity: warning}

  - alert: GPUThrottling
    expr: DCGM_FI_DEV_CLOCK_THROTTLE_REASONS &gt; 0
    for: 10m
    labels: {severity: warning}

  - alert: TrainerCPUThrottled
    expr: rate(container_cpu_cfs_throttled_periods_total{container=<span class="gm-s">"trainer"</span>}[5m])
        / rate(container_cpu_cfs_periods_total{container=<span class="gm-s">"trainer"</span>}[5m]) &gt; 0.05
    for: 10m
    labels: {severity: warning}
    annotations: {summary: <span class="gm-s">"Trainer {{ $labels.pod }} is CPU-throttled — should be Guaranteed with integer cores"</span>}</code></pre>
<div class="gm-warn"><b>Corrections to the original rules</b>The original memory rule divided by <code>DCGM_FI_DEV_FB_TOTAL</code>, which dcgm-exporter does not emit by default — use USED + FREE. The power rule used <code>DCGM_FI_DEV_POWER_MAX_LIMIT</code>, also not in the default collector set; the throttle-reasons bitmask is the direct signal. And "low utilization" should be scoped to GPUs that are <em>allocated</em> to a pod, otherwise every idle spare card pages you.</div>

## Inference-side SLO metrics

<ul>
<li>TTFT p50/p95/p99 and ITL p50/p99 per model (from the engine's own metrics or the gateway).</li>
<li>Queue depth and time-in-queue: the leading indicator of a capacity problem.</li>
<li>KV cache utilization and preemption count: high preemptions = you are over-admitting.</li>
<li>Prefix cache hit rate: if it drops, routing stickiness or cache tier sizing broke.</li>
<li>Error rates by class: 429 (rate limit — expected), 503 (capacity), 5xx from the engine (bug or GPU fault).</li>
</ul>
