## Capacity and fairness

<ul>
<li><strong>Token-bucket rate limits</strong> per API key/organization on requests-per-minute and tokens-per-minute (input and output counted separately). The router rejects with HTTP 429 and a <code>retry-after</code> before any GPU work is done.</li>
<li><strong>Priority tiers</strong>: interactive chat &gt; API &gt; batch. Batch APIs (24-hour turnaround, half price) exist precisely to soak up off-peak GPU capacity.</li>
<li><strong>Admission control</strong>: a request whose prompt would exceed available KV blocks waits in queue rather than evicting a running request (unless preemption is enabled, in which case a low-priority request's KV is swapped to host memory or recomputed later).</li>
<li><strong>Max output tokens</strong> caps let the scheduler bound how long a request will occupy its KV blocks.</li>
</ul>

## What breaks in production

<table>
<tbody><tr><th>Symptom</th><th>Usual cause</th><th>Fix</th></tr>
<tr><td>TTFT spikes for everyone when one user sends a 100k prompt</td><td>Prefill monopolizes the step</td><td>Chunked prefill (interleave prefill chunks with decode), or disaggregation</td></tr>
<tr><td>Throughput collapses at high concurrency</td><td>KV cache exhausted → preemption thrash</td><td>Cap max concurrency; quantize KV; more TP; GQA models</td></tr>
<tr><td>Cache hit rate low despite chat workload</td><td>Router not sticky to replica holding the prefix</td><td>Cache-aware routing; larger host-memory cache tier</td></tr>
<tr><td>Replica restarts take minutes</td><td>Weights loaded from object storage every time</td><td>Node-local NVMe weight cache; pre-warmed pools</td></tr>
<tr><td>Random NCCL hangs</td><td>One GPU in the TP group throttled / bad NVLink / Xid errors</td><td>DCGM health checks, node cordon, <code>nvidia-smi -q -d ERR</code></td></tr>
</tbody></table>
