## Streaming protocols

<table>
<tbody><tr><th>Protocol</th><th>How it works</th><th>Used by</th></tr>
<tr><td>Server-Sent Events (SSE)</td><td>Plain HTTP response with <code>Content-Type: text/event-stream</code>; server keeps the connection open and writes <code>data:</code> lines. One direction. Reconnect is trivial.</td><td>Anthropic Messages API, OpenAI API, most web chat UIs</td></tr>
<tr><td>WebSocket</td><td>Full-duplex persistent socket. Needed when the client also streams (voice, real-time audio, cancel mid-stream cheaply).</td><td>Realtime/voice APIs</td></tr>
<tr><td>gRPC streaming</td><td>HTTP/2 + protobuf, internal service-to-service.</td><td>gateway ↔ engine</td></tr>
</tbody></table>

## Where the CDN matters (and where it can't help)

<ul>
<li>It serves the UI bundle, fonts, and images from a point of presence near the user — that's why the app "loads instantly".</li>
<li>It terminates TLS and absorbs attack traffic, so the origin only sees clean requests.</li>
<li>It <em>cannot</em> cache chat responses (each one is unique), and it must be configured to pass streaming responses straight through — an edge that buffers responses turns a streaming chat into a 30-second stall followed by a wall of text.</li>
<li>Regional routing: the edge forwards to the nearest region that has GPU capacity for the requested model; some models only exist in some regions.</li>
</ul>
