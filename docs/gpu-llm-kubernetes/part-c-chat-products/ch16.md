## Tool use, concretely

<pre><code><span class="gm-c">// 1. Tools are declared as JSON schemas in the request</span>
"tools": [{
  "name": "kubectl_top_pods",
  "description": "Return CPU/memory usage of pods in a namespace",
  "input_schema": {"type":"object","properties":{"namespace":{"type":"string"}},"required":["namespace"]}
}]

<span class="gm-c">// 2. The model replies with a tool_use content block instead of prose</span>
{"type":"tool_use","id":"toolu_01","name":"kubectl_top_pods","input":{"namespace":"ml-training"}}

<span class="gm-c">// 3. Your code runs it and sends the result back as the next user message</span>
{"role":"user","content":[{"type":"tool_result","tool_use_id":"toolu_01","content":"trainer-0  7800m  60Gi\n…"}]}

<span class="gm-c">// 4. Model continues, possibly calling more tools, until end_turn</span></code></pre>

## MCP — Model Context Protocol

<p>MCP is an open protocol (introduced by Anthropic in 2024, now widely adopted) that standardizes how an AI application discovers and calls external tools, resources and prompts. Instead of every app hand-writing a Gmail integration and a GitHub integration, the service ships one <em>MCP server</em> and every MCP-capable client (Claude.ai, Claude Code, IDEs, other assistants) can use it.</p>

## Agent design patterns

<div class="gm-grid2">
<div class="gm-card"><b>Single-agent loop</b>One model, many tools, one context. Simplest and usually best. Claude Code is essentially this.</div>
<div class="gm-card"><b>Sub-agents</b>The main agent spawns a child with its own fresh context for a bounded task ("search the codebase for X") and gets back a summary. Keeps the parent's context small.</div>
<div class="gm-card"><b>Planner / executor</b>One call produces a plan (or todo list) that's kept in context; subsequent calls tick items off. Improves reliability on long tasks.</div>
<div class="gm-card"><b>Workflow (deterministic)</b>Fixed chain of LLM calls with code in between (classify → extract → draft). Not an agent — cheaper and more predictable when the steps are known.</div>
</div>

## Safety in agents

<ul>
<li><strong>Prompt injection</strong>: text a tool returns (a web page, an email) may contain instructions. The harness marks tool results as untrusted data and the model is trained not to follow instructions inside them; sensitive actions require user confirmation.</li>
<li><strong>Permissions</strong>: read-only by default; writes, deletes, payments and network access gated behind explicit approval or allow-lists.</li>
<li><strong>Sandboxes</strong>: code runs in a microVM/gVisor container with no credentials, egress allow-listed, filesystem reset per task.</li>
<li><strong>Budgets</strong>: max turns, max tokens, wall-clock limits, so a looping agent stops.</li>
</ul>
