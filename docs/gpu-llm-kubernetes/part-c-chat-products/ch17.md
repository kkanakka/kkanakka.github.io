## One turn, step by step

<div class="gm-timeline">
<div><b>00.0s</b>You type: "the training pod is CPU-throttled, fix the manifest".</div>
<div><b>00.1s</b>CLI assembles the prompt: system + CLAUDE.md ("we use Guaranteed QoS for trainers") + history + your message, and streams the API call.</div>
<div><b>01.2s</b>Model emits <code>tool_use: Grep {pattern: "nvidia.com/gpu", path: "k8s/"}</code>. Read-only → auto-allowed. CLI runs ripgrep, appends the result.</div>
<div><b>02.5s</b>Model emits <code>tool_use: Read {file: "k8s/trainer.yaml"}</code>. Result appended.</div>
<div><b>04.0s</b>Model emits <code>tool_use: Edit {file, old: "cpu: \"4000m\"\n limits: cpu: \"8\"", new: "cpu: \"8\"\n limits: cpu: \"8\""}</code>. Write → permission prompt shows a diff; you press y.</div>
<div><b>05.5s</b>Model emits <code>tool_use: Bash {cmd: "kubectl apply --dry-run=client -f k8s/trainer.yaml"}</code>. Bash → prompt; you allow. Output appended.</div>
<div><b>07.0s</b>Model emits text: "Requests and limits now match so the pod gets Guaranteed QoS and a pinned CPU set…" with <code>stop_reason: end_turn</code>. Turn ends; cost and context usage updated.</div>
</div>

## Configuration surfaces

<dl class="gm-kv">
<dt>CLAUDE.md</dt><dd>Markdown files at repo root, subdirectories and <code>~/.claude/</code>, loaded into every prompt. Conventions, build commands, "always run tests before committing".</dd>
<dt>settings.json</dt><dd>Permission allow/deny patterns, default model, environment variables, enabled MCP servers. Project-level file can be committed for the team.</dd>
<dt>Skills</dt><dd>Folders with a <code>SKILL.md</code> describing a procedure (how to build a PDF, house style for docs). Loaded on demand when relevant, keeping the base prompt small.</dd>
<dt>Hooks</dt><dd>Shell commands that run on events (before a tool call, after an edit, on stop). Used for auto-formatting, linting, blocking edits to certain paths.</dd>
<dt>Slash commands</dt><dd>Built-in (<code>/compact</code>, <code>/clear</code>, <code>/cost</code>, <code>/review</code>) and user-defined prompt templates in <code>.claude/commands/</code>.</dd>
<dt>Headless mode</dt><dd><code>claude -p "…"</code> runs one task non-interactively with JSON output — how CI pipelines and other programs drive it. The Agent SDK exposes the same loop as a library.</dd>
</dl>

## Why context management dominates CLI design

<p>A coding session reads many files and runs many commands; each result lands in context. A 200k window fills in an hour of heavy work. The CLI therefore: shows a context meter; truncates long outputs (e.g. only the first/last N lines of a log); prefers Grep over reading whole files; uses sub-agents for exploration so only a summary returns; and compacts automatically. Prompt caching (Chapter 10) is what keeps the repeated resending of a 100k-token session affordable — the CLI orders the prompt so the stable parts hit the cache.</p>
