## How it works

<img src="/diagrams/ch14/sequence.svg" alt="How it works" class="doc-diagram doc-diagram-seq" />

<!-- DIAGRAM:sequence:END -->
<p class="gm-lead">The model forgets everything the instant a response ends. "Memory" in a chat product is layered software around a stateless function: the transcript stored in a database, a prompt rebuilt each turn, KV caches that make rebuilding cheap, and increasingly a separate memory store the model reads from and writes to.</p>

## The layers of memory

<table>
<tbody><tr><th>Layer</th><th>Where it lives</th><th>Lifetime</th><th>What it does</th></tr>
<tr><td>KV cache</td><td>GPU HBM → host RAM</td><td>Seconds to minutes</td><td>Makes re-sending the transcript cheap. Not "memory" — a compute cache.</td></tr>
<tr><td>Conversation transcript</td><td>Relational DB (messages table)</td><td>Until deleted</td><td>The ground truth. Re-sent each turn within the window.</td></tr>
<tr><td>Rolling summary</td><td>DB, attached to conversation</td><td>Conversation</td><td>When history exceeds the window, older turns are compressed into a summary the model wrote.</td></tr>
<tr><td>Cross-chat memory</td><td>Memory store + vector index</td><td>Account</td><td>Facts/preferences extracted from past chats, retrieved by relevance and injected. Users can view/delete. Some products generate them automatically, others only from explicit "remember this".</td></tr>
<tr><td>Past-chat search</td><td>Search index over transcripts</td><td>Account</td><td>A tool the model calls ("conversation_search") to pull specific old chats into context on demand rather than always injecting them.</td></tr>
<tr><td>Project knowledge</td><td>Object storage + vector index</td><td>Project</td><td>Uploaded docs; chunked and retrieved (RAG) or, if small enough, placed entirely in the cached prefix.</td></tr>
<tr><td>Weights</td><td>Model parameters</td><td>Until retrained</td><td>What the model learned in training. Not updated by your conversations in production systems.</td></tr>
</tbody></table>

## Context-window management strategies

<ul>
<li><strong>Truncate oldest</strong> — simplest; loses early instructions. Always keep the system prompt.</li>
<li><strong>Summarize and compact</strong> — ask the model to summarize the oldest 60% of turns into a paragraph; replace them. Claude Code does this automatically ("compaction") when a session approaches the limit.</li>
<li><strong>Tool-result pruning</strong> — large tool outputs (file contents, search results) are the bulk of agent context; drop or shorten those older than N turns first.</li>
<li><strong>Externalize</strong> — write state to a file or DB and let the model retrieve it by tool call when needed (this is how long-running agents survive).</li>
</ul>
